How I work

Most of my work sits at the boundary between a fast API and a database that needs to stay fast under real load. I care about the parts that are easy to skip — connection pooling, query plans, retry logic, dead-letter queues — because that's usually where production incidents start. I'd rather ship something boring and reliable than something clever and fragile.

Real-Time Transaction Processing System

Financial transaction events needed to be processed reliably at high volume, without losing or duplicating records when producers or consumers failed.

JavaSpring BootKafkaMicroservices
My contribution

Sole backend engineer on the system — designed the event schema shared across producer and consumer services and implemented the failure-handling logic.

Engineering

Event-driven architecture with Kafka topics between producer and consumer microservices; dead-letter queues and retry policies for failed or malformed events; consumer group coordination across services.

Result

3x throughput improvement, 45% fewer failed transaction events, and message loss pushed to near-zero in production.

Technology

Java, Spring Boot, Apache Kafka, event-driven microservices.
